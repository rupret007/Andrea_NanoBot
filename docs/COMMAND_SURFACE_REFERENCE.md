# Andrea Command Surface Reference

This is the formal reference for Andrea's current command and feature surface.

Use it when you need the full inventory of:

- public-safe Telegram slash commands
- operator-only slash command families
- hidden/internal button-backing commands
- natural-language discovery surfaces
- operator status and proof scripts

For day-to-day user help, stay with `/start`, `/help`, `/commands`, `/features`, `/thinking`, `/council`, `/cognition`, `/memory`, `/learning`, and [USER_GUIDE.md](USER_GUIDE.md).

## Truth Model

Andrea separates surface truth this way:

- `user-facing`
  - normal conversation and the small public-safe Telegram command set
- `operator-facing`
  - setup, validation, troubleshooting, work cockpit, shopping approvals, and deeper control surfaces
- `internal`
  - button-backing commands and inline action ids that support the product but are not part of normal slash help

Current-host proof uses these labels:

- `live_proven`
  - the capability has passed the real proof bar on this host
- `near_live_only`
  - repo-side behavior is ready, but one fresh live proof leg is still missing
- `degraded_but_usable`
  - a bounded real path is usable, but the full live-proof bar is not yet met
- `externally_blocked`
  - repo-side behavior is not the problem; an external dependency or human-only step is still blocking proof

Surface-shape and access overlays still appear in this reference too:

- `bounded`
  - intentionally narrower or confirmation-first behavior, not a proof label
- `operator_only`
  - available only in the main Telegram control chat or operator docs
- `disabled`
  - accepted for compatibility but intentionally turned off

For launch-readiness specifically, operator surfaces also expose an overlay:

- `core_ready`
- `core_ready_with_manual_surface_sync`
- `provider_blocked_but_core_usable`
- `near_live_only`
- `externally_blocked`

The command and natural-language tables below are a capability inventory. Their
state columns record implementation boundaries and the most recent documented
release validation; it is **not** a freshness claim for every listed channel.
Only the current channel snapshot and live operator commands establish
per-host proof. Static docs should not overrule live host truth. When proof
state matters, use:

1. `npm run services:status`
2. `npm run setup -- --step verify` (live; may call a model and start a
   container execution probe)
3. `npm run debug:status`

Host note:

- The table records implemented capability; use the current channel snapshot
  and operator commands for Telegram, Alexa, and BlueBubbles freshness.
- On the current host, daily guidance still needs one fresh Telegram proof turn;
  this is proof debt, not an implementation failure.
- Calendar reads can be used for grounding. Every calendar write still requires
  a fresh, target-bound approval and postcondition verification.
- A clear calendar request followed by an explicit research clause can use the
  bounded compound path. The event draft is parsed from the calendar clause
  only, the research result is delivered separately, and neither leg grants the
  other new authority. A compound draft requires the targeted phrase
  `confirm calendar event`; bare acknowledgements do not write it. Generic
  `for me` wording does not opt personal Calendar, task, profile, or life-thread
  context into the outward research request.
- `Compare, explain, and saved context` should follow current provider health;
  configuration alone is not a live-health claim, and local or saved-context
  answers may remain available when an external provider is blocked.
- Durable recovery reads require an explicit request such as `resume the durable mission` or `continue the durable work`. Bare follow-ups such as `keep going` and `resume that` are not durable-recovery commands. A recovery read returns checkpoint-linked metadata and the next safe action; it does not create approval, consume a scoped resume grant, or restart an executor.
- Deep-work reconciliation treats a terminal runtime error as authoritative, carries suppressed stale-session-attempt evidence into a retry, and keeps coding/operator packets scope-blocked until the repository or exact operator target/action/postcondition is host-bound.
- On BlueBubbles, `@Andrea` wakes the Andrea companion path and `@OpenClaw` selects the OpenClaw/helper lane when the default trigger is in use.

- `/start`
  - onboarding and first-step orientation only
- `/help`
  - short usage guidance plus channel boundaries
- `/commands`
  - only the stable public-safe Telegram slash commands
- `/features`
  - capability families, flagship journeys, and current channel roles
- Operator docs
  - full slash-command inventory, hidden/internal backing commands, status scripts, and setup/release truth
